EVENT SUB CATEGORY - DEV PILOT HANDOVER
======================================

Status: 24 November 2026
Environment: DEV only

1. SUMMARY
----------

One Event Sub Category, Marathon, was created in Dynamics DEV using the
existing Azure Data Factory (ADF) dispatcher. It was linked provisionally to
the Event Category Sporting event. Dynamics readback confirmed the name,
Category, active status and ID; the same ID was captured in Snowflake XREF.

This proves one reference-record pilot, not a full Event Sub Category load.
It did not add a Sub Category to any Event or change an existing Event.
The source and Category mapping remain subject to business confirmation.

4. CODE CREATED OR CHANGED
--------------------------

Paths below are relative to the repository root.

CREATED:
  INTEGRATION_DB\DYNAMICS\Views\
    VW_D365_EVENTSUBCATEGORY_PILOT_REQUESTS_DEV.sql

  Produces the fixed Marathon request only when Marathon is present in the
  candidate source and no matching writeback state or pilot XREF exists.
  Uses the DEV Sporting event ID and the confirmed Dynamics navigation
  property mhnas_Category. It does not check the live Dynamics name.

CREATED:
  MDM_DB\GOLD\Procedures\
    SP_CAPTURE_EVENTSUBCATEGORY_PILOT_DEV.sql

  Checks the returned ID against the planned pilot ID and captures it in
  MDM_DB.GOLD.XREF. Conflicting or duplicate XREFs raise an error.
  Call only after a successful create or verified reconciliation.

CHANGED:
  ADF Pipeline\Dynamics\PL_D365_DISPATCHREQUESTS.json

  Three expressions in the existing dispatcher were extended:
  - LKP_GetRequests selects the pilot request view for this pipeline ID.
  - WEB_Post requests the Event Sub Category ID in the response.
  - SCR_CAPTURE_XREF calls the dedicated pilot capture procedure.

  No new ADF pipeline was created. The user validated and debug-ran the
  modified dispatcher in DEV. Compare the current ADF definition before
  replacing it: other changes or routes may have been made since this pilot.

DOCUMENTED:
  EVENT_MIGRATION_DEV_HANDOVER.md
  EVENT_SUBCATEGORY_DEV_HANDOVER.txt

The pilot view, procedure and dispatcher route are DEV-specific. Before
go-live, build and test an agreed full-load approach, then retire pilot
components only when no longer needed for reconciliation or reference.
Do not delete the XREF evidence without an agreed retention approach.

The ten names without an exact match at the time of the original check,
excluding the Marathon pilot, are:
  Abseil, Adventure Trek, Challenge, Half Marathon, Own Place, Skydive,
  Social, Student Trek, Trek and Virtual.

The source preview showed Social and Virtual under both Other and Sporting
event. A subcategory record has one Category lookup, so the intended
handling needs a decision. Walk, Cycle, Run and Trek/Hike already belong to
Sponsored Activity in Dynamics, not the provisional Sporting event Category.
It has not been established whether the Dynamics form filters or enforces
the Category/Sub Category combination.

Three RE Events had two distinct values:
  1293: Own Place and Marathon
  1428: Cycle and Virtual
  1433: Half Marathon and Virtual

The user agreed to hold these for subcategory mapping until a rule is
decided. No hold has been implemented and existing Events were not changed.
Other Events may have no subcategory value; the treatment of blank or missing
values also needs agreement.


6. QUESTIONS FOR THE BUSINESS
-----------------------------

These are advance questions; answers are not required yet.

1. Should the RE values recorded as Event Type Subcategory be used as Event
   Sub Categories in Dynamics?

2. Should we retain each of the 11 RE names that did not have an exact
   Dynamics match, or use broader existing names where appropriate, such as
   Run for Marathon? Marathon has been created provisionally in DEV.

3. Which Dynamics Category should each subcategory belong to? In particular,
   should Marathon be under Sporting event or Sponsored Activity?

4. Should we reuse existing Walk and Cycle even though they are linked to
   Sponsored Activity rather than our provisional Sporting event Category?

5. Social and Virtual appear under both Sporting event and Other in RE.
   Where should each sit in Dynamics?

6. Are Virtual and Own Place subcategories, or do they describe something
   else about an Event that should be recorded separately?

7. Where an Event has two subcategories, which should be used? Is there
   another place the second value should be recorded?

8. What should happen where an Event has a blank or missing subcategory?

9. Should subcategories be added to Events already migrated to Dynamics DEV?

10. Should the full migration include all historical Events and values, or
    only an agreed subset?

11. Are the four provisional Categories Other, Sporting event, Dinner and
    Class appropriate, or should existing Dynamics Categories be used instead?


7. SAFETY AND RESTART
---------------------

- Do not rerun this pilot as a way to load the remaining names: it is fixed
  to Marathon, and Marathon already exists.
- Run no overlapping pilot or other writer for the same record.
- The view excludes captured pilot IDs and writeback state, but it does not
  check live Dynamics for a matching name. Those checks do not protect
  against all duplicates or concurrent writes.
- If a create or ID capture has an uncertain outcome, check Dynamics and
  reconcile before retrying. Do not treat an empty preview as proof of
  successful migration.
- XREF records a captured ID, not live record status. Later changes or
  deletion in Dynamics require a current readback or reliable extract.
- Full-load processing, Event lookup updates, multi-value handling and the
  business mappings are not yet implemented or tested.
