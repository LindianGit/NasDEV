RAISERS EDGE TO SNOWFLAKE (DEV) - SOURCE TABLES AND TARGET TABLES
==================================================================
Source: AUDIT_DB.CONFIG.PIPELINE_METADATA rows saved in "Raisers Source Data.csv".
ADF is a black box. Every one of the 72 rows is SOURCE_TYPE = SQLSERVER, LOAD_TYPE = FULL, ENABLED = TRUE.
Target rule: source T_<Name>  ->  Snowflake table  RAISERS_EDGE.STG_T_<NAME IN CAPITALS>


  +---------------------------+     +---------------+     +-----------------------------------+
  | RAISERS EDGE DATABASE     |     | ADF           |     | SNOWFLAKE                         |
  | (SQL Server)              |     | (black box)   |     | schema RAISERS_EDGE               |
  |                           | --> | full copy of  | --> |                                   |
  | 72 source tables          |     | each table    |     | 72 landing tables                 |
  | T_<Name>                  |     |               |     | STG_T_<NAME>                      |
  +---------------------------+     +---------------+     +-----------------------------------+
                                                                          |
                                                                          v
                                          +------------------------------------------------------+
                                          | [step not seen] fills ODS_T_* from STG_T_*           |
                                          | RAW_PROD.RAISERS_EDGE.ODS_T_*  (has IS_DELETED)      |
                                          |   -> VW_ODS_T_*  WHERE NOT IS_DELETED  [VERIFIED DDL]|
                                          |   -> SP_ETL_RAISERS_EDGE -> STANDARDISED_RECORDS     |
                                          |   -> match -> golden                                 |
                                          +------------------------------------------------------+

     RAW_PROD.RAISERS_EDGE.ODS_T_ACTIONATTRIBUTES WHERE NOT IS_DELETED, with columns passed through unchanged.
   - ASSUMED for now: DEV's view layer reads PROD-named raw data (not a clean DEV/PROD separation).
   - The step that fills ODS_T_* from STG_T_* is not in the exports.
   - Marked * are the 9 tables the daily MDM procedure reads (through VW_ODS_T_<NAME>).
